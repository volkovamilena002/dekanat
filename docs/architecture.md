# Архитектура

## Почему такой стек
- **Next.js (App Router)** — фронтенд и бэкенд в одном приложении: серверные компоненты читают БД
  напрямую, формы работают через Server Actions. Меньше кода → меньше мест для ошибок ИИ.
- **PostgreSQL** — надёжная реляционная БД, масштабируется от прототипа до тысяч студентов
  (индексы, реплики, пулы соединений). Данные кабинета реляционные по природе: студент → группа →
  расписание → дисциплины → оценки.
- **embedded-postgres локально** — настоящий PostgreSQL, который ставится как npm-пакет и
  запускается скриптом `npm run dev:local` (без Docker и системной установки). Локально и в
  продакшене одна и та же СУБД, отличается только `DATABASE_URL`.
  Сначала пробовали PGlite (Postgres в WASM внутри процесса) — отказались, см. `ai-log.md`.
- **Drizzle ORM** — типизированные SQL-запросы, схема в TypeScript, миграции в виде SQL-файлов.

## Продакшен
Docker Compose: `caddy` (HTTPS, Let's Encrypt) → `app` (Next.js standalone, Node 24) → `db` (PostgreSQL 17).
Подключение к БД ленивое — сборка образа не требует базы. `/api/health` проверяет связь с БД.

## Масштабирование
- Приложение без состояния (сессии в БД) → можно запускать несколько экземпляров за балансировщиком.
- Индексы по `student_id`, `group_id`, `date` на всех «горячих» таблицах.
- Лимит попыток входа сейчас в памяти процесса; при нескольких экземплярах выносится в Redis/БД.

## Структура
```
src/
  app/
    login/            — вход
    (student)/        — кабинет студента (общий layout с навигацией)
      (home)/         — «Сегодня»
      schedule/       — расписание
      grades/         — успеваемость; electives/ — запись на дисциплины по выбору
      requests/       — заявки и справки: (list)/ — список и каталог, [id]/ — карточка и документ
      notifications/  — уведомления
      profile/        — профиль
    staff/            — кабинет сотрудника: заявки, schedule/ — изменения расписания, объявления
  db/
    schema.ts         — схема БД
    index.ts          — пул соединений node-postgres
    migrations/       — SQL-миграции (генерирует drizzle-kit)
  lib/
    auth/             — пароли, сессии, лимит попыток
    dal/              — Data Access Layer: все запросы с проверкой владельца
    time.ts           — даты и время в часовом поясе Москвы
  components/         — UI-компоненты
e2e/                  — автотесты Playwright и скриншоты для отчёта
scripts/
  local-pg.ts         — запуск локального PostgreSQL (общий для dev и автотестов)
  dev.ts              — локальный запуск: PostgreSQL + данные + next dev (--db-only — только база)
  setup-db.ts         — миграции + вымышленные данные
  migrate.ts          — только миграции
Dockerfile, docker-compose.yml, deploy/ — продакшен (см. deploy.md)
```

## Модель данных (кратко)
- `users` (логин, хеш пароля, роль, ФИО) → `students` (факультет, направление, курс, группа, зачётка).
- `groups`, `teachers`, `subjects`.
- `lessons` — конкретные занятия на даты семестра со статусом (`normal`/`moved`/`cancelled`/`room_changed`/`replaced`).
  Перенос = старая запись со статусом `moved` + новая запись в целевом слоте.
- `enrollments` (дисциплина студента в семестре, форма контроля, итог) → `assessments` (контрольные точки, баллы).
- `requests` (заявки) → `request_events` (история статусов).
- `notifications` (адресат: все / группа / студент) + `notification_reads`.
- `sessions` (SHA-256 токена, срок).
- `elective_rounds` (кампания записи: курс, семестр, сколько выбрать, срок) → `electives`
  (дисциплина, преподаватель, вместимость) → `elective_choices` (студент + электив).

## Скелетоны загрузки и статус 404
`loading.tsx` лежит только в разделах **без id в адресе** (`(home)`, `schedule`, `grades`,
`notifications`, `profile`, `requests/(list)`). Страницы `requests/[id]` рендерятся целиком до
отправки ответа: если заявка чужая, сервер успевает вернуть настоящий HTTP 404. Со скелетоном
ответ начинается со статуса 200 ещё до проверки владельца — данные не утекают, но статус «врёт».

## Тема оформления
Светлая (по умолчанию — даже если в системе включена тёмная), тёмная или «как в системе».
Выбор хранится в cookie `theme`; корневой layout читает её
и ставит `data-theme` на `<html>` ещё на сервере — страница не «мигает» светлой темой. Токены
цветов в `src/app/globals.css`; переключатели — `src/components/theme-toggle.tsx` (кнопка в
шапке, три варианта в боковом меню и профиле).

## Время
Все даты расписания — в часовом поясе Europe/Moscow (`src/lib/time.ts`), независимо от часового
пояса сервера.
