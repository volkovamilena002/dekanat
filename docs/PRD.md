# PRD: «Цифровой деканат будущего»

## Проблема
Учебная жизнь студента разбросана: расписание на сайте, оценки в отдельной системе, справки —
через очередь в деканате, объявления — в чатах и почте. С телефона найти нужное трудно.
Студент не понимает «как у меня дела» и узнаёт о переносах и дедлайнах слишком поздно.

## Решение
Один кабинет, который отвечает на три вопроса студента за пару касаний:
1. **Что у меня сейчас и что изменилось?** — экран «Сегодня».
2. **Как у меня дела с учёбой?** — успеваемость с понятным итогом и рисками.
3. **Как получить документ без очереди?** — заявки со статусом, как отслеживание посылки.

## Пользователи и роли
- **Студент** — видит только свои данные.
- **Сотрудник деканата** — обрабатывает заявки, публикует объявления и изменения расписания.

## Обязательное ядро (из ТЗ)
| Раздел | Что внутри | Статус |
|---|---|---|
| Вход и профиль | логин/пароль, ФИО, факультет, направление, курс, группа | готово |
| Расписание | сегодня и неделя, аудитория, преподаватель, заметные переносы/отмены; сотрудник переносит и отменяет пары | готово |
| Успеваемость | баллы по дисциплинам, зачёты/экзамены, сессия, итоговая картина; запись на элективы | готово |
| Заявки и справки | заказ справки/заявления онлайн, статус с историей | готово |
| Уведомления | новости деканата, дедлайны, изменения | готово |

## Идеи сверх ядра (приоритет сверху вниз)
Сделано: 1, 2, 3, 4, 7, 8, экспорт в календарь, проверка подлинности справки (`/verify`).

1. **Кабинет сотрудника** — студент подаёт заявку, сотрудник меняет статус, студент видит это сразу.
2. **Экран «Сегодня»** — следующая пара с таймером, изменения, дедлайны, активные заявки.
3. **Светофор успеваемости** — риск долга по каждой дисциплине, «сколько баллов не хватает».
4. **Заявка как трек посылки** — шкала статусов с датами; QR/код проверки подлинности справки.
5. **ИИ-помощник деканата** (GigaChat/YandexGPT через серверный прокси) — ответы по положениям
   вуза, помощь в заполнении заявления. Ключ только на сервере. **Отложено** (12.11): ТЗ его
   не требует, а ключ API — лишняя зависимость; вернёмся, если останется время.
6. PWA (установка на телефон), тёмная тема, экспорт расписания в календарь (.ics).
7. **Запись на элективы** — карточки дисциплин с живым счётчиком мест, лимит выбора, срок записи;
   последнее место не достанется двоим (блокировка строки в БД).
8. **Изменения расписания сотрудником** — перенос, отмена, смена аудитории, замена преподавателя
   с проверкой пересечений (группа, аудитория, преподаватель) и подсказкой свободных аудиторий;
   группа сразу получает уведомление.

## Нефункциональные требования
- Мобильная версия от 360 px, все сценарии проходятся с телефона.
- Безопасность — см. `security.md`.
- Только вымышленные данные; на сайте явно указано, что это концепт для конкурса; без логотипа вуза.
- Доступ из России без VPN до 28.11.2026 — хостинг на российском VPS.
- Минимум два тестовых студента с разными данными + аккаунт сотрудника.

## Сценарии для демонстрации жюри
1. Войти студентом → «Сегодня»: следующая пара, перенос, дедлайн.
2. Открыть расписание на неделю → увидеть отменённую/перенесённую пару.
3. Открыть успеваемость → понять, где риск долга.
4. Заказать справку → увидеть статус «Подана».
5. Войти сотрудником → взять заявку в работу → «Готова».
6. Снова студентом → статус обновился, пришло уведомление.
7. Попробовать открыть чужую заявку по адресу → 404.
8. Студенткой (Мария) записаться на элективы: одна дисциплина уже без мест, после двух выбранных
   остальные блокируются; отказаться — место освобождается.
9. Сотрудником открыть «Расписание» → перенести пару в занятое время (ошибка с причиной),
   затем в свободное → студент видит перенос в расписании и уведомление.
