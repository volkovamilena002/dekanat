код, документация, проверка в встроенном браузере.

## Этап 2. Ядро кабинета — 11.11.2026
**Что сделано ИИ:**
- Схема БД (14 таблиц), вход (argon2id, сессии в БД, лимит попыток), Data Access Layer.
- Скрипт вымышленных данных: целый семестр расписания с еженедельными переносами/заменами,
  баллы БРС, история оценок, заявки в разных статусах, уведомления. Три студента с разными
  профилями (отличница, «риск по сетям», первокурсник-контрактник с долгом) и сотрудник.
- Экраны: «Сегодня», расписание (неделя, изменения, экспорт .ics), успеваемость (светофор,
  прогноз оценки, допуск, стипендия, история), заявки (каталог, форма, трекер статусов,
  ответ на уточнение, отмена, печатный документ с кодом проверки), уведомления (фильтры,
  дедлайны), профиль, кабинет сотрудника (очередь заявок, смена статуса, объявления).
- Публичная страница `/verify` — проверка подлинности справки по коду.

**Проверки в браузере (встроенный браузер Claude):** вход, все разделы, подача заявки,
обработка сотрудником → уведомление студенту; студент Б открывает заявку студента А по
адресу → «Не найдено»; студент открывает `/staff` → перенаправление; ширина 375 px —
горизонтальной прокрутки нет ни на одной странице.

**Ошибки ИИ и как исправили:**
1. **PGlite не подошла.** ИИ выбрал встраиваемый Postgres (PGlite), чтобы не ставить СУБД.
   При проверке смены статуса сервер падал с `RuntimeError: Aborted()`. ИИ добавил
   диагностический лог и увидел, что Next.js 16 в dev-режиме рендерит страницы в
   **нескольких процессах** (разные PID), а PGlite допускает только один процесс на папку.
   Решение: перейти на настоящий PostgreSQL через пакет `embedded-postgres` и скрипт
   `npm run dev:local`. Правило записано в `CLAUDE.md`, чтобы агенты не повторили ошибку.
2. **Кодировка на Windows.** Первый запуск PostgreSQL создал базу в WIN1252 — кириллица не
   сохранялась. Исправлено флагами `--encoding=UTF8` и `template0`.
3. **Tailwind 4:** `@apply` нельзя применять к собственным классам — ИИ разнёс `.btn` и его
   варианты.
4. **Несоответствие данных:** подсказка на входе обещала «долг по матанализу», а долг
   по сгенерированным датам ещё не наступал — ИИ заметил это на скриншоте и сдвинул КТ.
5. **Пароли демо-аккаунтов** сначала были зашиты в клиентский компонент — перенесены на
   сервер с возможностью отключения (`SHOW_DEMO_ACCOUNTS=0`).

## Этап 3. Подготовка к хостингу — 11.11.2026
**Промпт:** «Что мы можем пока сделать без VPS и API-ключа?» → «Давай по этапам».

**Что сделано ИИ:**
- Продакшен-сборка `next build` — без ошибок.
- `Dockerfile` (многоэтапный: сборка → маленький образ `runner` без исходников; образ `tools`
  для миграций и демо-данных), `docker-compose.yml` (приложение + PostgreSQL 17 + Caddy с
  автоматическим HTTPS), `deploy/.env.example`, `docs/deploy.md` — пошаговая инструкция.
- `/api/health` — проверка, что сайт и база живы; `robots.txt` запрещает индексацию концепта.
- Учтены российские реалии: Docker из репозитория Ubuntu, зеркало Docker Hub, бесплатный
  адрес `*.sslip.io` для HTTPS без покупки домена.

**Проверка:** Docker на машине разработчика не установлен, поэтому ИИ проверил содержимое
образа по частям: собрал `standalone`-сервер **без доступа к БД** (как внутри Docker),
запустил `node server.js` против локального PostgreSQL — health, редирект без сессии,
заголовки безопасности и вход студента работают.

**Ошибка, найденная заранее:** подключение к БД создавалось при импорте модуля — сборка
в Docker упала бы без `DATABASE_URL`. ИИ сделал подключение ленивым (при первом запросе).

## Этап 4. Элективы и изменения расписания — 12.11.2026
**Решение до этапа:** ИИ-помощника внутри кабинета откладываем. ИИ сам признал, что эту идею
предложил он, а не ТЗ: критерий 2 оценивает ИИ в разработке, а не в продукте.

**Промпт:** «Да, этап 2» (элективы + перенос/отмена пар сотрудником).

**Что сделано ИИ:**
- Схема: `elective_rounds`, `electives`, `elective_choices` + миграция `drizzle-kit generate`.
  `npm run dev:local` теперь сам применяет новые миграции к существующей базе.
- Студент: страница «Дисциплины по выбору» — карточки со счётчиком мест, лимит 2, срок записи,
  отказ от выбора; плашка-вход на «Сегодня» и в «Учёбе».
- Сотрудник: вкладка «Расписание» — группа, неделя, пары дня; форма «Перенести / Отменить /
  Аудитория / Замена» с проверкой пересечений и подсказкой свободных аудиторий; группа сразу
  получает уведомление, сотрудник видит, скольким студентам оно ушло.
- Демо-данные: одногруппники (без возможности входа) — чтобы места на элективах были
  реально заняты; срок записи всегда в будущем относительно дня заполнения базы.

**Проверка (в браузере, вручную через ИИ-агента):** запись и отказ; серверный отказ при
«разблокированной» вручную кнопке (лимит и нет мест); перенос в занятый слот → понятная
ошибка; перенос в свободный слот и отмена → у студентки появились изменения в расписании
и уведомления; мобильная ширина 375 px без горизонтальной прокрутки; `tsc` и `eslint` чисто.

**Ошибки и находки ИИ:**
1. **React 19 очищает форму после отправки** — при ошибке пересечения сотрудник терял
   введённые дату и пару. ИИ поймал это при проверке и стал возвращать введённые значения.
2. **Старые огрехи демо-данных:** уведомления о переносах датировались будущим числом,
   а у «замены преподавателя» в карточке оставался прежний преподаватель. Исправлено в
   генераторе данных.
3. Линтер запретил объявлять компонент внутри компонента (`react-hooks/static-components`) —
   заменено на обычную функцию.

## Этап 5. Автотесты и скриншоты — 12.11.2026
**Промпт:** «Да, автотесты».

**Что сделано ИИ:**
- Playwright: 38 сценариев в `e2e/` — ядро ТЗ, сквозной путь справки (студент → сотрудник →
  уведомление → документ → проверка подлинности), элективы, изменения расписания, безопасность,
  вёрстка на 360 px.
- Тесты идут против **продакшен-сборки** и **отдельной базы** `dekanat_e2e`, которая
  пересоздаётся перед прогоном. Запуск PostgreSQL вынесен в `scripts/local-pg.ts` и общий с
  `dev:local`. Браузер — установленный Chrome, без скачивания Chromium.
- `npm run screenshots` — 25 скриншотов (телефон: светлая и тёмная тема, компьютер) в
  `docs/screenshots/` для этого отчёта.

**Первый прогон: 29 из 38.** Разбор падений:
1. **Настоящий баг вёрстки:** страница входа на 360 px была шире экрана (385 px). Сетка без явной
   колонки растягивалась по содержимому, а строки «логин / пароль» не переносились. Исправлено:
   `grid-cols-1`, на телефоне логин и пароль переносятся на отдельную строку.
2. **Чужая заявка отдавала HTTP 200** (с текстом «Не найдено», данные не утекали). Причина:
   общий `loading.tsx` начинал потоковую отдачу до проверки владельца, и статус уже нельзя
   было сменить. ИИ нашёл объяснение в документации Next.js 16 и разнёс скелетоны по
   разделам без id — теперь честный 404.
3. Шесть падений — ошибки самих тестов: служебный элемент Next.js `#__next-route-announcer__`
   тоже имеет `role="alert"`; неоднозначные селекторы. Исправлено в тестах.
4. ESLint начал проверять сгенерированный отчёт Playwright — добавлено исключение.

**Второй прогон: 38 из 38.**

**Что нашла проверка доступности:**

   затемнил 4 токена (`--ok`, `--info`, `--warn`, `--bad`) — исправление сразу на всех экранах.
2. Полупрозрачный текст на фиолетовой кнопке (4,41) — прозрачность уменьшена.
3. Ложная тревога «нет заголовка страницы»: axe запускался до того, как Next.js подставлял
   `<title>` после перехода. В тест добавлено ожидание заголовка.

**Что ИИ нашёл глазами на скриншотах:**

## Этап 7. Новая палитра и переключатель темы — 12.11.2026
**Промпт:** картинка с тремя цветами (Porcelain `#E8EBED`, Carbon `#17191D`, Ultramarine `#244CFF`)
и «хочу уйти от фиолетового… сделаем переключатель тёмная/светлая тема».

**Как ИИ подбирал цвета:** прежде чем менять, посчитал контраст. Белый текст на Ultramarine —
5,9 (хорошо), но Ultramarine как цвет текста на Carbon — всего 2,98 при норме 4,5. Поэтому
акцент разделён на два токена: `accent` (заливки, всегда Ultramarine) и `accent-ink`
(текст и обводки: в светлой теме тот же Ultramarine, в тёмной — светлый оттенок `#7A92FF`,
контраст 6,2). 42 места в коде переведены на новый токен автоматически.

**Переключатель темы:** кнопка в шапке (телефон, кабинет сотрудника, вход), три варианта
«Светлая / Тёмная / Как в системе» в боковом меню и в профиле. Выбор хранится в cookie, и
сервер сразу отдаёт страницу в нужной теме — без вспышки светлого экрана, как бывает при
хранении в localStorage. Вариант `dark:` в Tailwind настроен так, что учитывает и систему,
и выбор пользователя.

**Ошибка, пойманная на проверке:** на странице входа кнопка темы уехала влево — в классах
одновременно оказались `relative` и `absolute`. ИИ увидел это на скриншоте и исправил.

**Итог:** 49 автотестов из 49 (включая новый `e2e/theme.spec.ts` и проверку контраста всех
экранов в обеих темах), скриншоты пересняты в новой палитре.

**Доработка по просьбе:** «Давай, чтобы стандартная тема была белая, а не чёрная». Раньше без
выбора сайт следовал системе (на телефоне с тёмной темой открывался тёмным). Теперь по
умолчанию светлая тема, а тёмная — только по выбору пользователя (или «Как в системе»).
Цвет строки состояния браузера тоже берётся из выбора. В тестах доступности тёмную тему
теперь включают через cookie, как пользователь; добавлены проверки «система тёмная — сайт
светлый» и «“Как в системе” включает тёмную». Итог: 51 тест из 51.

## Этап 8. Демо-видео — 12.11.2026
**Промпты:** «Давай начнём с видео сценария» → «Сможешь ли ты это реализовать в видео?»

**Что сделано ИИ:**
- Сценарий на 5 минут (`docs/video-script.md`): 9 сцен, у каждой — свой критерий оценки, текст
  озвучки (~480 слов) и действия на экране; все надписи сверены с приложением.
- Автоматическая запись (`npm run video`): Playwright проходит сценарий в браузере как человек —
  видимый курсор, подсветка кликов, плавная прокрутка, субтитры и метка сцены поверх сайта.
  Слайды (титр, «Как работал ИИ», ошибки ИИ, автотесты, итог) — HTML в фирменной палитре.
  Кадры берутся из Chrome (CDP screencast) и собираются в WebM VP9 через ffmpeg, который уже есть
  у Playwright. Рядом — субтитры `.srt` с таймингом.
- Видео пишется только после того, как прошли все автотесты, поэтому «51 автотест» на слайде — правда.

**Проблемы и как их решили:**
1. Голоса нет: синтезатор речи Windows знает только английский, а урезанный ffmpeg не кодирует
   звук. Решение — субтитры с темпом под живую озвучку; голос накладывается в Clipchamp.
2. ffmpeg из Playwright не понимает `-i -` — нужен `pipe:0` (выяснено по списку протоколов).
3. Chrome отдаёт кадры в CSS-пикселях (1280×720) — видео в честных 720p без растягивания.
4. На просмотре кадров ИИ заметил: субтитр закрывал сообщение об ошибке, дата в форме
   была в американском формате, последний слайд обрезался, «51 автотестов». Всё исправлено.
