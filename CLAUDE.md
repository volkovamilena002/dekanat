# Цифровой деканат будущего — инструкции для ИИ-агентов

Прототип личного кабинета студента для конкурса. Это **концепт**, а не официальный сервис вуза.
Перед работой прочитай: `docs/PRD.md` (что строим), `docs/architecture.md` (как устроено),
`docs/security.md` (правила безопасности — обязательны).

## Стек
- Next.js 16 (App Router, `src/`), React 19, TypeScript, Tailwind CSS 4, иконки lucide-react.
- Next.js 16 отличается от того, что ты знаешь: middleware называется `proxy.ts`,
  `cookies()`/`params`/`searchParams` асинхронные. Сверяйся с `node_modules/next/dist/docs/`.
- `cacheComponents` выключен — не используй `'use cache'`.
- БД: Drizzle ORM + PostgreSQL через `DATABASE_URL`. Локально PostgreSQL поднимает
  `npm run dev:local` (пакет embedded-postgres, данные в `.data/postgres`). Схема: `src/db/schema.ts`.
  Не используй встраиваемые однопроцессные БД (PGlite, SQLite-файл): Next.js 16 в dev
  рендерит в нескольких процессах.
- Пароли: argon2id (`@node-rs/argon2`). Сессии: случайный токен в httpOnly-cookie,
  в БД хранится только SHA-256 от токена.

## Команды
- `npm run dev:local` — PostgreSQL + вымышленные данные (при первом запуске) + `next dev`.
- `npm run db:generate` — сгенерировать SQL-миграцию после правки схемы.
- `npm run db:setup` — пересоздать данные (нужен запущенный PostgreSQL и `DATABASE_URL`).
- `npm run lint`, `npx tsc --noEmit` — проверки перед коммитом.
- `npm run test:e2e` — автотесты Playwright (продакшен-сборка + отдельная база `dekanat_e2e`).
  Новая функция = новый сценарий в `e2e/`; правило безопасности = тест в `e2e/security.spec.ts`.
- `npm run screenshots` — скриншоты экранов в `docs/screenshots/` для отчёта.

## Правила кода
- Любой доступ к данным — только через `src/lib/dal/*` (Data Access Layer). Каждая функция DAL
  сама получает текущего пользователя через `requireStudent()` / `requireStaff()` и фильтрует
  по его id. Никогда не принимай `studentId` из URL, формы или клиента.
- Чужая запись = `notFound()` (404), а не 403 — не раскрываем существование записи.
- Server Actions повторно проверяют сессию и валидируют вход через zod.
- В клиентские компоненты передавай только нужные поля (никаких `passwordHash`, токенов).
- Секреты — только в переменных окружения на сервере. Никаких `NEXT_PUBLIC_` для ключей.
- Только вымышленные данные. Никаких реальных ФИО, номеров зачёток, логотипа вуза.
- Интерфейс на русском. Мобильная вёрстка с 360 px — проверяй каждый экран.
- Палитра: Porcelain `#e8ebed`, Carbon `#17191d`, Ultramarine `#244cff`. Акцент для заливок —
  `bg-accent`, для текста и обводок — `text-accent-ink` / `border-accent-ink` (в тёмной теме
  чистый Ultramarine на Carbon нечитаем). Тёмная тема — вариант `dark:` (учитывает выбор пользователя).
- Доступность WCAG 2.1 AA: цвета только из токенов `globals.css` (контраст уже проверен),
  у иконок-кнопок — `aria-label`, у полей — `<label>`. Новый экран добавь в `e2e/a11y.spec.ts`.
- У каждого списка есть пустое состояние, у каждой формы — ошибки и состояние отправки,
  у каждого раздела — `loading.tsx`-скелетон. Исключение: страницы с id в адресе
  (`requests/[id]`) — без скелетона, иначе чужой id вернёт 200 вместо 404 (см. architecture.md).
